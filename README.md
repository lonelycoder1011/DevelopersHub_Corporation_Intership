## 🌸 Task 1 — Iris Dataset EDA & Visualization

**Goal:** Explore and visualize the classic Iris dataset to understand feature distributions, class separability, and outliers — using `pandas`, `matplotlib`, and `seaborn`. No model training — pure EDA.

### Dataset

| Property | Value |
|---|---|
| Source | `seaborn.load_dataset('iris')` (UCI ML Repository) |
| Size | 150 samples × 5 columns |
| Target | `species` — setosa, versicolor, virginica |
| Features | sepal_length, sepal_width, petal_length, petal_width |

### Visualizations Produced

| Plot | Purpose |
|---|---|
| Pairplot (scatter matrix) | All feature relationships by species |
| Focused scatter plots | Best vs. worst feature pairs |
| Histograms + KDE | Feature value distributions per species |
| Box plots + Strip plots | Outlier detection per species |
| Correlation heatmap | Linear relationships between features |
| Violin plots | Distribution shape and spread |

### Key Findings

- **Petal features** (`petal_length`, `petal_width`) are the best discriminators — clean cluster separation between all three species
- **Iris setosa** is linearly separable from versicolor and virginica
- **Versicolor vs Virginica** overlap in sepal space — harder to distinguish
- Petal length and width are highly correlated (r = 0.96)
- No missing values; perfectly balanced dataset (50 samples per class)
- Minor outliers in `sepal_width` for setosa

### How to Run

```bash
pip install pandas numpy matplotlib seaborn
jupyter notebook Task1_Iris_EDA.ipynb
```

## 📈 Task 2 — Stock Price Prediction

**Goal:** Predict the next trading day's closing price using historical OHLCV data, engineered features, and two ML models — Linear Regression and Random Forest.

### Dataset

| Property | Value |
|---|---|
| Source | Yahoo Finance via `yfinance` |
| Default Stock | AAPL (Apple Inc.) |
| Period | 2 years (~504 trading days) |
| Features | Open, High, Low, Volume + 7 engineered features |
| Target | Next day's closing price |

Data is cached locally after first download — no internet needed on re-runs. To force a fresh download, delete the CSV in `data/`.

### Models

**Linear Regression (Baseline)** — fits a linear mapping from features to next-day close, scaled with `StandardScaler`. Learning curve generated by training on increasing data fractions (5% → 100%).

**Random Forest Regressor** — 100 trees, `max_depth=8`, `min_samples_leaf=5`, configured lightweight for laptop use. Loss curve built using `warm_start=True`, growing 5 trees at a time.

### Engineered Features

| Feature | Description |
|---|---|
| `Range` | High − Low (intraday spread) |
| `Prev_Close` | Yesterday's close (momentum anchor) |
| `SMA_5` / `SMA_10` | 5 and 10-day simple moving averages |
| `Volatility_5` | 5-day rolling standard deviation |
| `Return_1d` / `Return_5d` | 1-day and 5-day price return % |

### Output Files

| File | Description |
|---|---|
| `_1_eda.png` | Price history, volume, SMA overlay, returns distribution |
| `_2_loss_curves.png` | Train vs validation loss for both models |
| `_3_actual_vs_predicted.png` | Time-series comparison with shading |
| `_4_scatter.png` | Predicted vs Actual scatter with R² annotation |
| `_5_feature_importance.png` | Random Forest feature importance |
| `_6_error_distribution.png` | Error histograms with mean/std |
| `_7_dashboard.png` | Summary card: metrics + next-day forecast |
| `_metrics.csv` | MAE, RMSE, R², MAPE% for both models |

### Evaluation Metrics

| Metric | Meaning |
|---|---|
| MAE | Average dollar error |
| RMSE | Root mean squared error (penalises large errors more) |
| R² | Explained variance (1.0 = perfect) |
| MAPE% | Mean absolute percentage error |

## 🧠 Task 3 — Mental Health Chatbot (Mistral 7B + QLoRA)

**Goal:** Fine-tune Mistral-7B-Instruct-v0.3 to act as a compassionate mental health support assistant using QLoRA (4-bit quantization + LoRA adapters) on the EmpatheticDialogues dataset. Trained on Kaggle P100 GPU in ~92 minutes.

### Results

| Metric | DistilGPT2 Baseline | Mistral 7B QLoRA | Improvement |
|---|---|---|---|
| Empathy Score | 0.053 | 0.120 | **+126%** |
| Avg Response Length | 12 words | 54 words | **+350%** |
| Response Diversity (TTR) | 0.18 | 0.478 | **+166%** |
| Coherence | Gibberish / fragments | Full human-level paragraphs | ✓ |
| Train Loss | — | 1.1573 | — |
| Best Eval Loss | — | 1.1521 | — |

> **Note on empathy score:** The 0.120 is based on a limited keyword list and understates real quality. Responses like *"I completely understand how you feel"* and *"It sounds like you have been struggling"* are genuinely empathetic but fall outside the keyword filter.

### Example Outputs

```
User:      I have been feeling really anxious about my job interview tomorrow.
Assistant: I completely understand how you feel! Job interviews can be nerve-wracking.
           What kind of position is it for? Just remember to relax and breathe. It's
           okay if you don't get everything right on your first try.

User:      I feel so alone lately. Nobody really understands what I am going through.
Assistant: It sounds like you have been struggling recently. Would it be helpful for
           me to try and offer some advice or just listen? Sometimes people just need
           someone to hear them out without any judgement.

User:      I feel like a burden to everyone around me.
Assistant: Oh no, you aren't a burden at all! It sounds like you are going through a
           really difficult time right now...
```

### Model Details

| Parameter | Value |
|---|---|
| Base model | mistralai/Mistral-7B-Instruct-v0.3 |
| Training method | QLoRA (4-bit NF4 + LoRA) |
| Dataset | EmpatheticDialogues (3,000 pairs) |
| LoRA rank / alpha | 16 / 32 |
| Target modules | q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj |
| Trainable parameters | 41.9M — only **1.1%** of 3.8B total |
| Epochs | 2 |
| Effective batch size | 32 (4 × 8 gradient accumulation) |
| Optimizer | paged_adamw_32bit |
| Learning rate | 2e-4 |
| Training hardware | Kaggle P100 16GB |
| Training time | ~88 minutes |
| Adapter size | 167.8 MB |
| Merged model size | 4.6 GB (fp16) |

### How QLoRA Works

```
Mistral 7B Base (frozen, 4-bit)   ← 3.76B params, ~3.5 GB VRAM
        +
LoRA Adapters (trainable)         ← 41.9M params, ~300 MB
        =
Fine-tuned Mental Health Model    ← Only 1.1% of params trained
```

1. **4-bit NF4 quantization** — base model ~4× smaller in VRAM
2. **LoRA adapters** — only small rank-16 matrices trained, not the full model
3. **Gradient checkpointing** — recomputes activations to save VRAM during backprop
4. **Paged AdamW** — optimizer states paged to CPU RAM when VRAM is tight

### How to Use Locally

**Option A — Merged model (easiest, ~4.6 GB, no extra libraries)**

```python
from transformers import AutoTokenizer, AutoModelForCausalLM
import torch

tokenizer = AutoTokenizer.from_pretrained("path/to/mistral_mental_health/final")
model = AutoModelForCausalLM.from_pretrained(
    "path/to/mistral_mental_health/final",
    torch_dtype=torch.float16,
    device_map="auto",
)
model.config.use_cache = True
model.eval()
```

**Option B — Adapter only (~168 MB, needs base model from HuggingFace)**

```python
from peft import PeftModel
model = PeftModel.from_pretrained(base_model, "path/to/mistral_mental_health/adapter")
```

### Training on Kaggle (Steps to Reproduce)

1. Accept Mistral license at [huggingface.co/mistralai/Mistral-7B-Instruct-v0.3](https://huggingface.co/mistralai/Mistral-7B-Instruct-v0.3)
2. Create a HuggingFace Read token at [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens)
3. In Kaggle: **Add-ons → Secrets → Add New Secret** → Name: `HF_TOKEN`
4. Set **Settings → Accelerator → GPU P100**
5. Run `mistral_qlora_finetune.ipynb` — completes in ~90 minutes

### Known Limitations

- Trained on 3,000 samples — more data would improve emotion coverage
- Not a replacement for professional mental health support
- Empathy keyword scorer underestimates real response quality
- Depressed and angry categories score lower — underrepresented in 3k sample slice
